# NEAR

Приватное пространство для пары на расстоянии. MVP: Django 5.2 / DRF / PostgreSQL, Flutter / Provider / Dio, JWT, приватный AWS S3.

## Структура

- `backend/core/models.py` — сущности пары, ежедневные ритуалы, конверты, история, карта и желания.
- `backend/core/serializers.py` — валидация и фильтрация скрытых данных.
- `backend/core/views.py` — авторизация, привязка пары, раскрытие заданий, архив, свидания.
- `backend/core/tests/` — интеграционные проверки доступа и бизнес-правил.
- `mobile/lib/` — пять основных вкладок, новые разделы из Home, onboarding, формы, состояние и REST-клиент.
- `docs/API.md` — контракт API и принятые решения.

## Backend: быстрый запуск

Нужны Docker и Docker Compose. Команды выполняются из корня проекта.

```sh
cp backend/.env.example backend/.env
# Укажите случайный SECRET_KEY и пароль PostgreSQL в backend/.env.
docker compose up --build -d
docker compose exec api python manage.py migrate
docker compose exec api python manage.py seed_content
```

API: `http://localhost:8000/api/`. Миграции не запускаются одновременно несколькими web workers. `seed_content` идемпотентно создаёт год вопросов и заданий; повторяющиеся тексты — стартовый контент, который можно заменить редакционным.

Локально без Docker (Python 3.12 рекомендован):

```sh
cd backend
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
set -a
. ./.env
set +a
# Для локальной PostgreSQL задайте POSTGRES_HOST=localhost.
python manage.py migrate
python manage.py seed_content
python manage.py runserver 0.0.0.0:8000
```

Быстрые тесты без PostgreSQL:

```sh
cd backend
SECRET_KEY=local-test-only-secret-which-is-long-enough DEBUG=1 TEST_SQLITE=1 .venv/bin/python manage.py test
```

Полные проверки БД выполняйте с PostgreSQL; SQLite не воспроизводит блокировки `SELECT FOR UPDATE`. Пользователь БД тестов должен иметь право создавать тестовую БД.

## Flutter

Приложение использует Material 3, тёплые цвета Deep Coral / Rose / Beige / Slate. Интерфейс на английском, как в задании. Отдельный wireframe не был приложен: дизайн реализован по текстовому описанию.

```sh
cd mobile
python3 tool/bootstrap.py
flutter pub get
flutter analyze
flutter test
# Android Emulator:
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/
# iOS Simulator:
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/
# Физическое устройство / release:
flutter run --dart-define=API_BASE_URL=https://your-api.example/api/
```

Нативные каталоги `ios/` и `android/` создаются командой `tool/bootstrap.py` из официального шаблона установленного Flutter SDK; скрипт сохраняет исходники приложения и добавляет разрешения для фото и сети. Повторный запуск сохраняет существующие runners.

Адрес API должен завершаться `/api/`. Для устройства укажите доступный HTTPS-сервер и его домен в ALLOWED_HOSTS. Не используйте development HTTP URL в релизе. Сборка iOS требует macOS/Xcode и настройки команды подписи Apple; Android — Android SDK/JDK.

Первый пользователь регистрируется и создаёт пространство. В Home → Our space копирует код. Второй пользователь регистрируется и присоединяется по коду. Затем оба могут загружать фото, отвечать, приглашать на свидание. Потяните экран вниз для обновления; данные также обновляются при возвращении в приложение. Push и realtime не входят в эту версию.

## Приватность и бизнес-правила

- Все API кроме регистрации и JWT требуют авторизацию; запросы ограничены текущей парой.
- Фото партнёра отсутствует в ответе API до двух загрузок. Скрытый ответ заменён `null`. Архив соблюдает те же правила.
- Для пары используется один IANA timezone, по умолчанию UTC. Его можно изменить в Home → Our space. Время свиданий отправляется в UTC, отображается по часовому поясу устройства.
- Одно фото и один ответ в день. Они неизменяемы; это исключает удаление своего вклада после раскрытия.
- Фото ежедневного ритуала до 10 MB и 25 MP пересохраняются как JPEG без EXIF/GPS. В модели хранится приватный ключ объекта, `photo_url` вычисляется при разрешённой выдаче.
- S3: включите Block Public Access, приватный bucket и минимальную IAM policy на его префикс. Заполните S3_BUCKET, регион и credentials, предпочтительно выдавайте права через роль. Ссылки действуют 5 минут.
- Без S3 файлы доступны только через защищённый Django endpoint. Не публикуйте каталог media через nginx/CDN.
- Инвайт случайный, одноразовый, можно перевыпустить. Привязка сериализуется блокировками пользователя и пары. `User.couple` — каноническое членство; меняйте его только через сервис привязки.
- Только приглашённый партнёр может перевести будущее свидание из pending в accepted или declined. Другие изменения статуса запрещены.
- Our Map вычисляет расстояние по вручную указанным координатам обоих партнёров; без них показывает сохранённое расстояние. GPS не собирается. Числа дней, встреч и воспоминаний вычисляются по данным, а не зашиты в UI.

## Перед публичным релизом

Это исходники MVP, а не аттестация готовности инфраструктуры. Настройте HTTPS, S3, секреты, резервные копии, наблюдаемость, подпись приложений и проверьте реальную загрузку фото на двух устройствах. Установите DEBUG=0, корректный ALLOWED_HOSTS и выполните `python manage.py check --deploy` с production-настройками. За TLS-прокси корректно настройте заголовки доверенного прокси; не доверяйте пользовательскому X-Forwarded-Proto.

DRF throttling по умолчанию использует локальный cache: для нескольких workers нужен общий cache и ограничение частоты на gateway. Email verification, восстановление пароля, удаление аккаунта/пары, push и модерация не включены в согласованный функциональный MVP, но нужны для полноценного публичного продукта. После logout refresh отзывается, выданный access JWT истекает в течение 15 минут. Уже раскрытую информацию нельзя отозвать у получателя.

Официальные основы: [Django custom User](https://docs.djangoproject.com/en/5.2/topics/auth/customizing/), [DRF permissions](https://www.django-rest-framework.org/api-guide/permissions/), [Flutter secure storage](https://pub.dev/packages/flutter_secure_storage).


## Near: ежедневные ритуалы

Пять разделов: Home, Daily Photo, Dates, Countdown, Questions. Memories и настройки пары доступны из верхней панели Home.

- Home показывает дни вместе и на расстоянии, расстояние, следующую встречу, фото, вопрос и ближайшее свидание.
- Фото доступны на Home в течение 24 часов после загрузки. Daily Photo использует общий день пары. Memories сохраняет все дни и автоматически собирает месячные капсулы; внутри они открываются от первого дня к последнему.
- В Questions ответы открываются по кнопке Reveal после двух ответов. Категории: Fun, Deep, Future, Random.
- В Dates восемь вариантов занятия, отдельное поле фильма/плана, сообщение, дата и время. Получатель может принять, отклонить или предложить другое время; последнее возвращает приглашение исходному отправителю для подтверждения.
- Countdown хранит встречи, годовщины, дни рождения, поездки и другие события. Home использует только ближайшее событие типа meeting.

После обновления примените миграции: `python manage.py migrate`, затем `python manage.py seed_content`. Идентификаторы существующих нативных приложений сохранены, отображаемое название — Near.


## Функции 6–10

Новые разделы доступны с Home. Фоны остаются однотонными или градиентными; фотографии используются только как пользовательские вложения.

6. **🎭 Mood** — ежедневный вопрос `How are you feeling today?` в общем часовом поясе пары; варианты `😊 Happy`, `🥰 Loved`, `😴 Tired`, `🥹 Missing you`, `😔 Sad`, `😡 Angry`. Статус партнёра имеет вид `Aisha is feeling 🥹 Missing you`. `Send hug 🫂` сохраняет объятие в общих сообщениях, `Send message` открывает переписку. Прошлая отметка обозначена как последняя; вопрос возвращается в новый день при обновлении или возврате в приложение.
7. **💌 Open When** — три предложенных заголовка и собственный триггер, текст, несколько фото, видео и голосовых аудиофайлов. В конверте доступны просмотр фото и воспроизведение видео/аудио. До 12 вложений по 50 MB. Конверты открываются пользователем по смыслу заголовка; автоматической блокировки по эмоции или дате нет.
8. **📖 Our Story** — события с датой, фото (до 10 MB), местом, описанием и своим эмодзи; порядок от ранних к поздним. Примеры из задания не создаются как реальные события пары.
9. **📍 Our Map** — вертикальный блок `YOU 📍 / ↓ / 3,870 km / ↑ / PARTNER 📍`, рассчитанный по координатам либо сохранённому расстоянию. Памятные места отображаются на локальной векторной карте. Местоположение вводится вручную; его можно перестать показывать. Карта не отправляет координаты внешним сервисам. Контуры: Natural Earth, public domain; источник указан в `mobile/assets/maps/README.md`.
10. **✨ Our Wishlist** — выбранное дополнение к заданию: общий список желаний с отметкой выполнения.

Миграция `0005` добавляет новые таблицы и поля. После обновления сервера выполните `python manage.py migrate`. Все новые endpoints и вложения требуют JWT и ограничены текущей парой; медиасервер поддерживает Range для воспроизведения видео. Голосовые сообщения загружаются как готовые аудиофайлы; запись микрофона и push-уведомления не добавлены.


### Исправления Questions и Countdown

Fun, Deep, Future и Random теперь выбирают вопрос дня для пары, а не просто показывают текущую категорию. Выбор доступен до первого ответа; после него приложение объясняет, почему смена закрыта. Выбранный вопрос виден обоим партнёрам и сохраняется в архиве. Для этого добавлена миграция `0006`.

На Home и в Countdown добавлены Edit/Delete. Форма редактирует название, место, тип и дату существующего события без создания дубликатов. Our space → Next meeting также открывает редактирование текущей встречи. После удаления автоматически показывается следующая встреча, если она есть.

### Шаринг геолокации и расстояние

В карточке пары на Home доступна кнопка `Share my location`. Приложение запрашивает доступ к геолокации только при нажатии, сохраняет координаты в приватном пространстве пары и, когда оба партнёра поделились позицией, заменяет ручное значение расстояния на расчёт по координатам. Повторное нажатие обновляет позицию. В `Our Map` доступны тот же системный шаринг, ручной ввод координат и отключение шаринга. Фоновое отслеживание не используется.
